# Pastline: правила для Claude Code

Персональний щоденник із lexical, semantic і hybrid пошуком та Ask Pastline. Один продукт і один диплом.

## Джерела правди

- `PLAN.md`: план, архітектура, диплом, журнал рішень (розділ 14), прогрес (розділ 15).
- `LABS.md`: лабораторні 01–05.
- Перед роботою прочитати розділ 15 `PLAN.md` і відповідний розділ плану або `LABS.md`.

## Режими роботи

- **Лабораторні (`labs/`): весь код пише користувач.** Claude лише пояснює теорію, рецензує (`review, do not rewrite`, один мінімальний фікс на баг) і опитує. Код лаби не редагує, якщо прямо не попросили.
  - Кожна лаба є незалежним проєктом у своїй папці; лаби 02–05 мають власний `pom.xml` і Java-пакет `lab02`, `lab03`, ...
  - README `labs/0X-.../README.md` з висновками Claude пише лише після опитування і після питань про все, чого не видно в коді чи таблиці результатів у `LABS.md`; немає даних → `TODO`.
- **Застосунок: код пише Claude.** Один чекпоінт за сесію (перший незавершений), спершу план, файли не редагувати до погодження. Готово лише з зеленим `mvn verify` (показати вивід). Після чекпоінта один рядок у розділ 14 `PLAN.md`: рішення, причина, альтернатива, питання комісії.
- **Експеримент:** запити, мітки, аналіз і висновки робить користувач; Claude пише раннер і графіки.
- **Текст диплома:** пише користувач; Claude допомагає зі структурою, перевіряє факти й логіку, рецензує.

## Архітектура (обов'язково)

- Модульний моноліт: один Spring Boot застосунок у `backend/`.
- Пакети за фічами `com.pastline.{auth,journal,importing,search,ai,shared}`, усередині звичні шари: `controller`, `service`, `repository`, `entity`, `dto`, `exception`, за потреби `security`, `config`, `client`. Без інтерфейсу `Service` + `ServiceImpl`, коли реалізація одна.
- API: JSON під `/api/v1/...`, DTO замість JPA-сутностей, UUID назовні, помилки `{ code, message, requestId, fieldErrors }`.
- Auth: Spring Security, серверна сесія з HttpOnly cookie, CSRF. Без JWT.
- Ізоляція: кожен запит до записів фільтрується за користувачем у SQL; `userId` від клієнта не є доказом власності.
- БД: PostgreSQL + pgvector у Docker Compose, схема лише через Flyway, `ddl-auto=validate`.
- AI за портом `EmbeddingModelPort`: домен не знає про Ollama чи Spring AI. Локально Ollama, профіль `cloud` (онлайн-демо) OpenAI.
- Власна таблиця embeddings, не `PgVectorStore`: фільтр користувача в SQL, `content_hash`, статус.
- Тести: Testcontainers із pgvector-образом, не H2.
- Форматування: Spotless (palantir-java-format). Перед комітом користувач запускає `mvnw spotless:apply`; Claude пише код у тому ж стилі.
- Логи: ніколи не логувати текст записів, паролі, cookies.
- Lombok дозволено: `@Getter`, `@RequiredArgsConstructor`, `@NoArgsConstructor(access = PROTECTED)` для JPA, `@Slf4j`. Не використовувати `@Data`, `@EqualsAndHashCode`, `@ToString` на JPA-сутностях; DTO — records.
- Без мікросервісів, Kafka, черг, CQRS, JWT.
- Версії Spring Boot, Spring AI, образу pgvector звіряти з офіційною документацією.

## Чого Claude не робить ніколи

- не комітить і не пушить без прямого дозволу;
- не додає `Co-Authored-By` чи інші AI-трейлери;
- не змінює `PLAN.md` без прямого прохання; без прохання можна лише розділи 14 і 15;
- **не створює нових планових чи документаційних файлів** без прохання;
- не вигадує результатів, версій, API;
- не пише код лаб; у README лаб не вписує того, чого користувач не робив;
- не ставить мітки релевантності й не пише висновки експерименту;
- не пише розділи диплома замість користувача;
- не кладе реальні особисті записи в репозиторій; не комітить `.env` і ключі.
