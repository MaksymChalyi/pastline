# Експеримент: методика

Опис того, **як** отримано числа. Висновки й інтерпретацію пише автор у тексті записки (див. кінець файлу).
Таблиці з числами — `results-tables.md`, рисунки — `../figures/`.

## Гіпотези (з `PLAN.md`, розділ 1.3)

- **H1.** Семантичний пошук підвищує recall для перефразованих запитів із малим збігом слів.
- **H2.** Лексичний пошук не гірший або кращий для точних імен, ідентифікаторів і рідкісних термінів.
- **H3.** Гібридний пошук підвищує загальну релевантність на змішаних типах запитів.
- **H4.** Семантичний і гібридний пошук додають вимірювану затримку.
- **H5.** Перевірка ідентифікаторів джерел після генерації зменшує кількість вигаданих фактів у відповідях Ask Pastline.

## Дані

**Корпус** — `docs/experiments/corpus-v1/corpus.json`: 520 синтетичних записів щоденника за 2024-11-01 — 2026-10-31,
згенерованих детермінованим скриптом `scripts/generate-corpus/GenerateCorpus.java` (SHA-256 у `corpus.sha256`).
Записи складаються з 128 цільових речень (`queries-v1/targets.json`, теми: робота, фінанси, здоров'я, сім'я,
подорожі, навчання, спорт, дім), частина з яких має еквіваленти іншою мовою (українська / англійська). Реальних
записів у корпусі немає.

**Запити пошуку** — `docs/experiments/queries-v1/`, 102 запити до цільових речень:

| Джерело | Запитів | Як отримано |
|---|---|---|
| `author.json` | 10 | автор, за інструкцією `AUTHOR.md` |
| `claude.json` | 42 | мовна модель Claude |
| `chatgpt.json` | 25 | мовна модель ChatGPT, фіксований промпт `PROMPT.md` |
| `deepseek.json` | 25 | мовна модель DeepSeek, той самий промпт |

Частину запитів згенеровано мовними моделями за фіксованим промптом (додаток із промптом — `PROMPT.md`);
метрики наводяться окремо для кожного джерела. Відповіді моделей збережено без редагування.

Типи запитів: `exact` (точний рідкісний термін), `wordform` (інша словоформа), `paraphrase` (перефразування без
спільних значущих слів), `crosslingual` (інша мова).

**Питання Ask Pastline** — `docs/experiments/ask-v1/questions.json`: 20 питань (згенеровано мовною моделлю,
`source: claude`): 15 мають відповідь у корпусі (з цілями з `targets.json`), 5 — не мають (тем немає в корпусі,
перевірено пошуком слів по корпусу).

## Еталон релевантності

Запис релевантний запиту, якщо містить хоча б одне цільове речення запиту або його еквівалент іншою мовою.
Еталон обчислюється автоматично з корпусу, без ручних міток, тож однаковий для всіх режимів.

## Метрики пошуку

Глибина — top-10.

- **Hit@k** (k = 1, 5, 10) — частка запитів, де хоча б один релевантний запис серед перших k.
- **MRR@10** — середнє 1 / ранг першого релевантного (0, якщо його немає в top-10).
- **Recall@10** — знайдені релевантні в top-10, поділені на min(10, кількість релевантних); нормування потрібне,
  бо в запиту буває до 32 релевантних записів.
- **Затримка** — час виклику `SearchService` без HTTP (включно з обчисленням вектора запиту): 5 прогрівних
  запитів, потім кожен запит 5 разів; p50 і p95 методом найближчого рангу за всіма вимірами режиму.

Якість рахується з першого виміряного прогону: пошук детермінований.

## Метрики Ask Pastline

Кожне питання проходить через справжній `AskService` один раз, `temperature = 0`. Зберігається сира відповідь
моделі (до перевірки) і фінальна (після).

- правильні відповіді / хибні відмови — на питаннях з відповіддю;
- правильні відмови / відповіді без підстав — на питаннях без відповіді;
- вигадані посилання — `[E#]` у сирій відповіді, яких не було в контексті;
- речення, прибрані перевіркою; відповіді, заблоковані перевіркою повністю;
- точність процитованих джерел — частка процитованих записів, що містять цільове речення;
- наявність релевантного запису в контексті (повнота пошуку для Ask);
- **точність переказу** — вручну, колонка `accurate` у `run-ask-*.csv`.

## Умови

- Локальний ноутбук без GPU: Ollama на CPU, PostgreSQL 17 + pgvector 0.8.2 у Docker, Java 21.
- Моделі: `embeddinggemma` з префіксами запиту/документа (768 вимірів), `qwen3:4b-instruct` для відповідей.
- Гібридний пошук: RRF k = 60, top-50 кандидатів з кожного режиму; параметри на наборі запитів не підбиралися.
- Кожен звіт містить конфігурацію і SHA-256 корпусу та файлів запитів — прогін можна повторити й перевірити,
  що дані ті самі (`running.md`, розділ 5).

## Що варто врахувати під час інтерпретації (умови, а не висновки)

- Корпус синтетичний: одне цільове речення повторюється в 5–32 записах.
- 92 зі 102 запитів і всі питання Ask Pastline створені мовними моделями.
- Одна модель ембедінгів і одна модель відповідей; кожен запит оцінено одним прогоном.
- Затримка виміряна на одному ноутбуці без GPU, разом з іншими процесами системи.
