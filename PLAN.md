# 1. ЩО БУДУЄМО І ЩО ДОВОДИМО

## 1.1 Проєкт

**Pastline**: персональний щоденник із пошуком по власних записах трьома способами (лексичний, семантичний, гібридний) і відповідями на питання з посиланням на джерела.

**Тема (робоча):** "Інтелектуальна система обліку та інтелектуального пошуку персональних записів". Фінальна назва має збігатися із затвердженою.

**Проблема:** людина пам'ятає зміст запису, але не точні слова. Пошук за ключовими словами такі записи пропускає.

## 1.2 Дослідницьке питання

> Як лексичний, семантичний і гібридний пошук порівнюються за релевантністю і затримкою під час пошуку персональних записів щоденника, зокрема для українськомовних запитів?

## 1.3 Гіпотези (перевіряю, а не припускаю)

- **H1.** Семантичний пошук підвищує recall для перефразованих запитів із малим збігом слів.
- **H2.** Лексичний пошук не гірший або кращий для точних імен, ідентифікаторів і рідкісних термінів.
- **H3.** Гібридний пошук підвищує загальну релевантність на змішаних типах запитів.
- **H4.** Семантичний і гібридний пошук додають вимірювану затримку.
- **H5.** Перевірка ідентифікаторів джерел після генерації зменшує кількість вигаданих фактів у відповідях Ask Pastline.

Відкинута гіпотеза, описана чесно, теж є результатом.

## 1.4 Мінімум, без якого диплом не захистити

- [ ] CRUD записів зі строгою ізоляцією користувачів
- [ ] лексичний, семантичний, гібридний пошук
- [ ] імпорт JSON
- [ ] синтетичний корпус 500+ записів із фіксованим seed
- [ ] 60+ розмічених запитів
- [ ] Recall@10, MRR, nDCG@10, p50/p95 для трьох режимів
- [ ] аналіз помилок і загрози валідності
- [ ] демо, яке не падає

# 6. ЗАСТОСУНОК (ПИШЕ CLAUDE CODE)

## 6.0 Архітектура (обов'язково)

- **Модульний моноліт:** один Spring Boot застосунок у `backend/`.
- **Пакети за фічами:** `com.pastline.{auth, journal, importing, search, ai, shared}`, усередині `api`, `application`, `domain`, `infrastructure`.
- **API:** JSON під `/api/v1/...`, DTO замість JPA-сутностей, UUID назовні, єдиний формат помилок `{ code, message, requestId, fieldErrors }`.
- **Auth:** Spring Security, серверна сесія з HttpOnly cookie, CSRF. Без JWT.
- **Ізоляція:** кожен запит до записів фільтрується за користувачем **у SQL**. `userId` від клієнта не є доказом власності.
- **БД:** PostgreSQL + pgvector у Docker Compose, схема лише через Flyway, `ddl-auto=validate`.
- **AI за портом** `EmbeddingModelPort`: доменний код не знає про Ollama чи Spring AI. Локально Ollama, онлайн-демо (профіль `cloud`) OpenAI за тим самим портом.
- **Власна таблиця embeddings, а не `PgVectorStore`:** потрібні фільтр користувача в SQL, `content_hash` і статус.
- **Тести:** Testcontainers із pgvector-образом, не H2.
- **Логи:** ніколи не логувати текст записів, паролі, cookies.
- **Без:** Lombok, мікросервісів, Kafka, черг, CQRS, JWT.
- Версії Spring Boot, Spring AI, образу pgvector звіряти з офіційною документацією.

## 6.0.1 Схема БД

```text
users             (id uuid, email unique, password_hash, timezone, created_at, updated_at)
journal_entries   (id uuid, user_id, title null, content, entry_date, content_hash,
                   created_at, updated_at, search_vector tsvector)
                   unique (user_id, entry_date, content_hash)
entry_embeddings  (entry_id, embedding vector(N), model, content_hash, status, created_at)
```
`N` дорівнює довжині вектора моделі (з Лаби 01).

## 6.1 Каркас і БД (02.11)
Spring Boot, `docker-compose.yml` з pgvector, Flyway V1 (`CREATE EXTENSION vector`), Actuator health.
**Готово, коли:** `docker compose up -d` і `mvn verify` зелені.

## 6.2 Auth (02–03.11)
Реєстрація, логін, логаут, `GET /api/v1/me`.
**Готово, коли:** тести на реєстрацію, логін, 401 без сесії.

## 6.3 CRUD записів (03–04.11)
`POST/GET/PUT/DELETE /api/v1/entries`, пагінація, фільтр за датою.
**Готово, коли:** **тест ізоляції** (A отримує 404 на запис B) і валідаційні тести.

## 6.4 Імпорт і корпус (04–05.11)
`POST /api/v1/import?dryRun=true|false` для JSON і Markdown; dry-run показує кількість, дати, дублікати, помилки. Ідемпотентність: `sha256(текст) + entry_date + user_id`. Помилка одного запису не зупиняє імпорт.
Генератор корпусу `scripts/generate-corpus`: 500+ записів UA/EN, фіксований seed → `docs/experiments/corpus-v1/corpus.json` + SHA-256.
**Готово, коли:** повторний імпорт додає 0; тест імпортує 500 записів.

## 6.5 Лексичний пошук (06.11)
PostgreSQL FTS, конфігурація `simple` (української стемінгу немає), GIN-індекс, `websearch_to_tsquery`, `ts_rank`. `GET /api/v1/search?q=...&mode=lexical`.
**Готово, коли:** тести знайдено / не знайдено / ізоляція; `EXPLAIN ANALYZE` використовує індекс.

## 6.6 Семантичний пошук (07–08.11)
Embeddings через порт, exact пошук pgvector `<=>`. Перерахунок при зміні `content_hash`, видалення з записом, статус `PENDING/READY/FAILED`, команда reindex. Фільтр користувача у SQL.
**Готово, коли:** `mode=semantic` працює; редагування оновлює вектор; тест ізоляції.

> **GATE 1 (08.11).**

## 6.7 Гібридний пошук (09.11)
Top-50 з обох, RRF: `Σ 1/(k + rank)`, k=60 як параметр. У debug-режимі ранги й RRF score.
**Готово, коли:** юніт-тести RRF; один запит у трьох режимах через одне API.

## 6.8 React-клієнт (10–11.11)
Vite + React + TypeScript: login, register, timeline, редактор, пошук із перемикачем режиму, сторінка Ask Pastline. Один HTTP-клієнт із `credentials: 'include'` і обробкою 401.
**Готово, коли:** створюю запис і знаходжу його трьома режимами з браузера.

## 6.9 Бенчмарк-раннер (11–12.11)
Читає корпус і запити, рахує метрики для кожного режиму, пише JSON у `docs/experiments/results/`. Warm-up 5, 20 повторів, p50/p95.
**Готово, коли:** одна команда видає JSON для трьох режимів.

> **GATE 2 (12.11).**

## 6.10 Ask Pastline (13–14.11)
`POST /api/v1/ai/ask`: hybrid top-K → контекст `<entry id date>` → модель → відповідь із `[id]`.
- відповідь лише з записів; текст записів це дані, не інструкції;
- **пост-валідація:** кожен `[id]` має бути серед знайдених, інакше речення видаляється;
- відповідь без перевірених джерел не показується;
- немає доказів → явна відмова: що шукали.

**Готово, коли:** тест з "отруєною" відповіддю (вигаданий id) не пропускає її.

> **Застосунок готовий до експерименту (14.11).**

# 7. ДЕПЛОЙ (24.11–05.12)

- **Фронтенд:** Vercel, rewrite `/api/*` → бекенд, щоб cookie була на одному домені.
- **Бекенд:** Render, профіль `cloud`, embeddings через OpenAI за `EmbeddingModelPort`. Безкоштовний сервіс засинає після 15 хв і прокидається ~1 хв, тому на грудень краще Starter.
- **БД:** окрема Postgres. Безкоштовна Render Postgres видаляється через 30 днів після створення і не має бекапів. Підтримку pgvector перевірити **до 24.11**.
- Корпус імпортується з `corpus.json`.
- **Онлайн-версія є демо з іншою embedding-моделлю. Її числа ніколи не йдуть у диплом.**

**Готово, коли:** логін, пошук і Ask Pastline працюють за публічною адресою; localhost лишається запасним варіантом для захисту.

# 8. ЕКСПЕРИМЕНТ (Я РОБЛЮ САМ)

## 8.1 Запити (06–10.11)
`docs/experiments/queries-v1.json`, **60–80 запитів**, ≥20% без відповіді. Частина від 3 людей: їм дати лише опис тем корпусу ("щоденник Java-розробника за 2 роки: робота, навчання, подорожі, здоров'я, фінанси, друзі"), без записів, по 10 запитів кожному. Категорії: точне слово, ім'я/назва, перефразування, синонім, спогад за змістом, опечатка, відмінкова форма, змішана мова, без відповіді. **Фіксую до першого прогону.**

## 8.2 Розмітка (10–13.11)
Спершу пишу правила (0 нерелевантний, 1 частково, 2 прямо). Кандидати: top-20 трьох режимів + ручний пошук. Мітки ставлю вручну. Через ≥3 дні перерозмічаю 20 запитів і рахую узгодженість.

## 8.3 Метрики
| Метрика | Що показує |
|---|---|
| Recall@10 | частка релевантних у top-10 |
| MRR | наскільки високо перший релевантний |
| nDCG@10 | якість ранжування з оцінками 0/1/2 |
| p50 / p95, мс | типова і погана затримка |

Окремо за категоріями запитів. Для Ask Pastline: ~20 питань із валідацією і без, рахую вигадані факти, неіснуючі id, правильні відмови.

## 8.4 Прогін і аналіз (14–16.11)
Повний прогін, сирі JSON, графіки **лише зі сирих файлів**. ≥10 провалів: запит, що очікував, що дав кожен режим, чому.

## 8.5 Загрози валідності
Синтетичний корпус; один анотатор, який є автором системи; упередженість запитів; pooling розмітки; одна модель і одне залізо; лише UA/EN; вирізаний query routing; дрейф версій. Формулювання "на оціненому наборі", не "доведено".

## 8.6 Freeze (16.11)
`docs/experiments/FREEZE.md`: git SHA, SHA-256 корпусу, запитів і міток, моделі, параметри RRF, версії PostgreSQL/pgvector, залізо, команда запуску, дата.
